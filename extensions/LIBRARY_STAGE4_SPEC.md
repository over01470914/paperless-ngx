## Daily UI and authenticated bridge

Preserve `/radar/`, native routes and existing map/list behavior. Add `/library/` as a cohesive daily screen with articles, ingestion batches, item reasons and supplementation. Chinese labels map the existing fixed category IDs; unmapped IDs render 未分類 rather than a fabricated category. Show completeness, publication date/date unknown, freshness caveat, source, original evidence and analysis separately. Support text/link submission, true attachment upload into a protected accepted staging root, item resume, cancel, and native read/star/pending state. No placeholder article dataset or fake progress. Poll only visible active batches with bounded intervals; distinguish complete from complete-with-unresolved items.

Native browser authentication remains native session/cookies. No service/admin token in JS, HTML, localStorage or browser configuration. The loopback bridge validates the caller session against the fixed native API before forwarding an exact allowlisted Library operation. Source inspection confirms `/api/ui_settings/` supplies current `user.id` and permission names, whereas `/api/profile/` DOES NOT contain a user ID and includes auth_token; use only the necessary ui_settings identity fields and never return/log profile tokens. Authorize ingestion mutations only for explicitly configured Boss user ID 2 with required native add/change document permissions; unknown identities fail closed. Read-only identities must not gain writer privileges through this bridge.

Every mutation requires exact allowed Host/Origin, a valid native session and native-compatible CSRF cookie/header validation (including masked token handling). Reject absent/mismatched tokens and cross-origin writes before reaching the service. Do not manufacture native sessions or set privileged auth cookies from untrusted input. Ordinary document/state reads and writes use native permission-aware APIs where possible. Companion proxy preserves native cookie/CSRF semantics; source URL/body instructions remain untrusted.

An unauthenticated preview may show shell/forms/help and an explicit Sign in later entry, but cannot submit, enumerate private batches, invent articles, create auth tokens or save library data. Real authenticated browser acceptance must be distinguished from an isolated API-authenticated screenshot harness. Remote Windows devices currently offline are a separate unverified gate.
