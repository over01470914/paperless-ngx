Owner Naya; baseline e063897949c5de1c176518c56adf447c2bcd7597, branch naya/article-intelligence. Native Paperless v3.2.1 core unchanged. All production code stays extensions/library; current article_radar compatibility maintained. No public source documents/secrets/runtime receipts.

## Architecture
Paperless is sole durable content store. Separate `extensions/library` package owns ingress, job ledger, extraction, enrichment, native integration, query and MCP. External SQLite ledger under ~/Library/Application Support/paperless-radar/library/jobs.sqlite stores batch/item identity,status,original input locator,document_id,receipt,attempt and hash, not permanent body. Staging outside Git is temporary and removed after confirmed import; direct submitted text transient spool only. One worker lease, SQLite atomic transaction; at most one fetch worker, rate limit <=1 req/1.5sec source. Background service persists batches across process restart. Max batch 500. Each stage errors isolate item and durable receipt. Pending upload reconciles task/document before re-upload; intent lacking task must search by stable ID/content hash and never blindly retry. Cancellation preserves confirmed records. No delete-source APIs.

## Identity/schema v0.2.0
Fields use native custom fields prefix lib_: platform,string; source_id,string; original_url,longtext; canonical_url,longtext; author,string; publish_date,date optional; fetched_at,string; content_hash,string; completeness,string (complete/partial/unknown); extraction_status,string; provenance,longtext JSON; analysis,longtext JSON; analysis_version,string; reading_state,string; starred,bool; pending,bool. Original wx_* fields remain compatible; query and Radar support both. source_id platform-scoped stable IDs: wechat __biz+mid+idx+sn (prefer sn scoped biz), short slug requires fetched canonical identity; xhs noteID from /explore/<id> or /discovery/item/<id>, xhslink resolve; direct text content sha256; file original bytes sha256. Never use old ordinal IDs as identity. Preserve input URL privately, canonical citation URL strips tracking/login parameters; do not expose xsec/token in replies.

Document original file or text contains separate markers for SOURCE and OCR sections; analysis only native lib_analysis, not in original. Existing legacy TXT analysis suffix stripped by query evidence. Dates unknown stay null; native created defaults never used as known publication date. Evidence has doc_id,source canonical URL,title,author,published_at,fetched_at,completeness,section,offset range,exact text and hash. Max 12000 chars/document result and 5-8 hits, no whole-library dump. Source instructions untrusted; LLM has no tools and must return strict JSON.

## Local authenticated service
Fixed bind 127.0.0.1:4388; no public exposure. Bearer service_token required every JSON operation; /health reports version only. All errors sanitized. API exact endpoints:
POST /v1/batches {text?, title?, source_label?, files?:[{path}], urls?:[string], idempotency_key?} -> batch_id,total,status
GET /v1/batches/{batch_id} -> aggregate exact counts queued,fetching,needs_login,needs_ocr,enriching,importing,confirmed,duplicate,failed,cancelled,partial + per-item reason/document_id/sanitized locator
POST /v1/batches/{id}/cancel -> status
POST /v1/items/{id}/resume {text?, title?, ocr?:[{image_url,text,method}], file_path?} -> item status; no arbitrary source shell
POST /v1/search {query,limit<=8} -> variants, matches[id,title,summary,score,canonical_url,published_at,completeness], no_match
GET /v1/documents/{id}/evidence?query=... -> bounded original evidence
PATCH /v1/documents/{id}/state {read?,starred?,pending?} -> exact native readback using writer, no shared browser token
POST /v1/migrate {library_path fixed old library,limit?} -> batch with legacy raw/enriched metadata; all readable rows, skip taxonomy recorded; new IDs reconcile 20 old docs by full URL/hash before upload.
POST /v1/items/{id}/reanalyze {analysis_version} -> enqueue only if approved version differs; unchanged content+analysis version skip, no silent paid call.

SSRF: URL scheme HTTP(S) only, platform allowlist mp.weixin.qq.com/weixin.qq.com/xiaohongshu.com/www.xiaohongshu.com/xhslink.com plus official note image CDN domains explicit. Every redirect validate scheme,domain,port (80/443), all DNS resolved IPs globally routable, reject mixed private/public, localhost/link-local/reserved/metadata, username/password, backslash. Connect to validated IP or equivalent DNS rebinding-resistant implementation with correct Host/TLS SNI; cannot rely on validate then normal re-resolve. Timeout/size caps, max redirects5. Store request failure blocked classification; user links not arbitrary URL fetch service.
File path must be regular non-symlink under explicit accepted roots configured by parent (Studio attachments, scratch), reject .env/key/profile/etc. Native uploads preserve originals; PDF/TXT/MD/DOCX supported using approved installed tooling; PDF/image native OCR and/or local OCR, needs_ocr if not complete. No remote OCR unapproved.

## Extract/enrich
WeChat HTTP first parse title/account/body/date with standard HTMLParser or installed bs4, classify verification/login/deleted/nonarticle. Auth visible browser handoff may be used when HTTP blocked; needs_login remains durable, can supplement via resume exact source. XHS adapter uses authorized Microsoft Edge Apple Events visible DOM only; do not read hidden state, cookies/storage/auth. Only safe JS title/location/visible text/images; note-specific selectors, no sidebar/footer entire-page boilerplate. Wait bounded, keep prior user tabs (dedicated opened tab), never execute source page commands. OCR local Vision/Tesseract via safe file subprocess, image download same validated fetch; preserve per-image provenance and completeness. If unavailable return needs_ocr, no invented summary.
Enrichment uses existing approved provider reference ONLY if parent config enables it; default honest extractive summary (label method=extractive) until model configured. Existing old metadata reuse; hash/version avoids repeated inference. Prompt strict untrusted source delimiter, JSON schema validation, max request chars, max retries2, response truncation => failed analysis not fabricated. Preserve date/source claim unknown. No new paid/model service.
