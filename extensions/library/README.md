# Paperless Library 0.3.0 source lane

This package provides durable ingress, a private SQLite job ledger, WeChat/text/file import adapters, a visible Edge XHS adapter, local image OCR, bounded native-reader search/evidence, a loopback authenticated API, and a FastMCP stdio facade. The Edge and OCR paths use synthetic tests in this lane; live desktop permissions, OCR engine behavior, native binary retention, and real source outcomes remain owner acceptance. UI, deployment, and live migration are not part of this source lane.

## Dependencies

Use the parent-provisioned Python 3.11 environment. Runtime pin: `mcp>=1.30,<2`; `beautifulsoup4`, `opencc-python-reimplemented`, and `PyMuPDF` are optional extraction/search enhancements. The package itself uses the standard library for its HTTP API and ledger.

## Parent bootstrap

Parent creates native `library-reader` and `library-writer` restricted identities, configures native visibility, and creates an external mode-0600 JSON file (normally `~/.config/paperless-ngx/library.json`):

```json
{"native_url":"http://127.0.0.1:4386","reader_token":"[external]","writer_token":"[external]","service_token":"[external]","runtime_dir":"~/Library/Application Support/paperless-radar/library","allowed_file_roots":["/approved/attachments"],"legacy_library":"/parent-owned/old-library","service_url":"http://127.0.0.1:4388","rate_limit_seconds":1.5,"reader_user_id":101,"writer_user_id":102,"boss_user_id":103}
```

`runtime_dir` is outside Git; it contains a mode-0600 ledger and mode-0700 staging directory. `allowed_file_roots` must be explicit directories; only regular TXT, MD, PDF, and DOCX files are accepted. The three native user IDs are mandatory: successful imports grant reader/boss view and writer/boss change permissions after task completion, then require reader readback. Start with `python -m extensions.library.app` and register `python -m extensions.library.mcp_server` with the parent MCP profile. Registration, credentials, roles, live service startup, and real source ingestion remain parent-owned.

The service starts its owned background worker thread before accepting requests. Ledger access is serialized with a reentrant lock; leases use persisted epoch time so expired fetching/importing claims recover after restart. Native-task polling has its own delayed schedule and does not consume source retry attempts. An uncertain intent without a task reconciles readable native records before becoming blocked; it is never blindly uploaded again. The fixed `legacy_library` is read only by `/v1/migrate`; it preserves usable legacy analysis metadata and records skipped unreadable rows. Existing readable Paperless documents are reconciled by matching source identity or compatible public and legacy URLs before upload; content hash is a fallback only when neither side has a source identity or URL.

Resume responses expose only sanitized item fields. WeChat shortlink supplements require a verified public canonical article URL supplied with `provenance=operator-public` or derived from publicly returned article HTML. The original private URL remains in the ledger. URL supplements may be text or an accepted-root file; binary bytes, title, known author/date/fetch time and metadata provenance are preserved. Unknown publication dates stay null. `source_label` is accepted and stored in native provenance. For a confirmed URL item with a real document ID, `resume` accepts only verified public canonical URL, author, publication date, and fetch time with `provenance=operator-public`; it patches metadata custom fields and a provenance revision, then requires restricted-reader exact readback. It does not upload or edit body content. File imports upload original bytes with filename/MIME; server-side original-file retention remains a parent real-native check.

XHS capture creates a dedicated Edge tab and reads only fixed note selectors for visible title, text, location and image references. When the note root is absent, bounded visible page markers distinguish login, risk, and deleted states; page boilerplate never becomes note body. A missing interactive desktop or login yields `needs_login`; source timeout and identity problems are separate blocked outcomes. Short XHS links pass through the DNS-pinned fetcher before the browser. Images use a separate exact-host CDN allowlist, MIME and signature validation, byte caps, installed Tesseract or install-free macOS Swift Vision. Visible text with unprocessed images is `partial`; image-only notes without OCR are `needs_ocr`. No remote OCR or inferred image text is used. Source, OCR and AI provenance are stored separately. Changed confirmed source content creates a separate revision document with prior document ID and stable source ID in provenance; no unverified Paperless core versions API is assumed.

The service binds only to `127.0.0.1:4388`. An existing owner-managed authenticated tailnet bridge is a separate operator exception, not direct binding or exposure by this service.

SubmitBatch and ResumeItem `text` accept at most 100000 Unicode code points (`len(text)` in Python), not 100000 encoded bytes. Independently, the **entire** request object, including optional fields and any extra fields, must fit in 131072 UTF-8 bytes after `json.dumps(value, ensure_ascii=True, separators=(",", ":"))`; input is rejected, never truncated. HTTP additionally rejects a raw `Content-Length`/body over 131072 bytes. For example, each `繁` is one character and three raw UTF-8 bytes, but becomes six ASCII bytes (`\u7e41`) in canonical JSON; `"` and `\` also expand to escaped JSON bytes. Thus a 100000-character text can still exceed the object cap, and whitespace can make a raw HTTP body exceed its cap even when canonical JSON fits. Both MCP tool input schemas advertise the 100000-character string cap and allow null, but the schema alone cannot enforce whole-object or wire byte limits. MCP calls pass through the same HTTP validation: its default JSON serializer includes spaces and, for `submit_batch`, optional null fields, so its actual wire size may exceed the compact canonical object size.

Optional approved enrichment is disabled unless `enrichment_enabled` is true. When enabled, configuration must set `enrichment_endpoint` to the parent-approved compatible endpoint, `enrichment_model` to `deepseek-v4.1-flash`, `enrichment_key_file` to an external mode-0600 reference containing the existing `DASHSCOPE_API_KEY`, and `enrichment_version`. The key is read only at an enabled request; it is never logged or stored. Calls are bounded to two attempts and require a non-truncated strict JSON response. Default analysis remains labelled `method=extractive`.

Search uses the native reader's permission-aware DRF `search` parameter, not `query`. It issues at most eight balanced exact-term variants, preserving English tokens and expanding fixed aliases and Chinese terms in both OpenCC directions. Evidence is exact source text only. Legacy citations resolve numeric `wx_source_url`, `wx_publish_date`, and `wx_enrichment` fields through the native custom-field schema; public citations canonicalize the URL.

WeChat parsing tracks the actual `#js_content` root boundary, ignores void/self-closing elements and hidden/script/style descendants, and gives a nonempty article body precedence over page chrome. Article prose mentioning verification or login is not treated as a gate. Credentialed input URLs are rejected before batch creation, and public locators never include userinfo.

OCR for a text source is included in the original text upload as separate SOURCE and OCR sections. After native task completion, the restricted reader must find the exact OCR section before a custom-field patch records `ocr_indexed=true` and the intended completeness. PDF/DOCX imports upload the original binary bytes; after the native task, OCR is appended to the reader's actual extracted `content` with a `content` and custom-field PATCH. The existing source content is kept byte for byte, and retries with the same OCR do not append another section. Conflicting OCR, failed PATCH, or inexact independent reader readback leaves the item `partial` or `needs_ocr` with its document ID and OCR staging reference for reconciliation; it is never uploaded again. A later custom-field patch and exact readback must record `ocr_indexed=true` before confirmation. Outstanding note images keep completeness `partial`. The owner's no-op native content PATCH and original-download readback are live evidence for that no-op only; changed-content PATCH and original-download preservation remain owner acceptance. Reanalysis queues only an existing confirmed document, never reuploads; it compares a normalized archived-source hash held in analysis metadata before approving the configured analysis version, then patches and reads back analysis fields.
